🔧 Présentation de n8n

n-odematio-n

Pourquoi n8n ?

  • No-code/Low-code (Workflow visuel)
  • Automatisation accessible même aux non-développeurs
  • Open Source 🥨 et en constante évolution (2.20.8)
n8n permet de connecter facilement tous vos outils : API, bases de données, services cloud. L'interface visuelle rend l'automatisation accessible même aux non-développeurs. Et contrairement à Zapier, vous gardez le contrôle de vos données.

À quoi ressemble un workflow n8n ?

  • Trigger : Déclencheur (webhook, email, cron...)
  • Nodes : Actions connectées visuellement
  • Variables : Données partagées entre étapes
  • Embranchements : Switch, Merge, Boucle, If, Filtre, ...
  • Exécution : Flux automatisé de bout en bout
Un workflow n8n, c'est une suite d'actions connectées visuellement. Ça commence par un trigger (webhook, email, planification), puis des nodes qui s'exécutent en séquence ou en parallèle, avec des variables qui circulent entre les étapes. Simple et puissant !

Qu'est-ce qu'un agent IA ?

  • 🧠 Modèle IA : Le cerveau (Krang)
  • 🤖 Agent : Le corps cyborg qui agit
  • 📝 Prompt système : Les instructions de base
  • 🛠️ Outils : Les complices (Shredder, Bebop, Rocksteady)

Agent = Modèle + Prompt + Outils

Le cerveau qui orchestre tout ! 🧠

Un agent IA, c'est comme dans les Tortues Ninja : Krang est le cerveau (le modèle IA), le corps cyborg c'est l'agent qui peut agir, et ses outils ce sont ses complices Shredder, Bebop et Rocksteady qui l'aident à accomplir ses missions !

AI Agent Node

  • Cerveau décisionnel
  • Prompts système / utilisateur
  • Intégrations natives
L'AI Agent Node est le cerveau de votre workflow. Il peut prendre des décisions, définir son comportement via prompts système, s'intégrer nativement aux workflows n8n, et planifier des actions complexes en les décomposant selon le contexte. Pssssst... c'est du LangChain sous le capot !

Configuration des Prompts

🎯 Prompt Système

  • Définit le comportement
  • Contexte permanent
  • Rôle de l'assistant
  • Contraintes globales

💬 Prompt Utilisateur

  • Instructions spécifiques
  • Données contextuelles
  • Variables dynamiques
  • Format de sortie
System: "Tu es un expert technique qui répond de manière claire et précise."
User: "Explique comment {{ $json.technology }} fonctionne en {{ $json.level }} phrases."
Dans n8n, vous configurez deux types de prompts. Le prompt système définit le comportement général : le rôle, le ton, et les contraintes de l'IA. Le prompt utilisateur contient les instructions spécifiques et peut utiliser des variables dynamiques du workflow. Cette séparation permet une grande flexibilité et réutilisabilité.

Qu'est-ce qu'Ollama ?

  • Docker pour l'IA : Conteneurise vos LLMs
  • Installation simple : Une commande
  • Local first : Vos données restent chez vous
  • API compatible : OpenAI-like
curl -fsSL https://ollama.com/install.sh | sh ⚠️
ollama run llama3.2
Ollama, c'est un peu le Docker de l'IA : il vous permet de télécharger, installer et faire tourner des modèles comme Llama, Mistral ou Qwen en local facilement. Plus besoin de Python complexe, juste deux commandes et vous avez votre IA perso qui tourne !

Intégration Ollama

Ollama est parfait pour l'IA locale. Installation simple, données privées, pas de coûts récurrents. Vous pouvez aussi l'installer sur un serveur distant pour partager les ressources GPU avec votre équipe. Dans n8n, il suffit de configurer l'URL de base et choisir le modèle.

Ollama local vs distant

🏠 Ollama Local

  • Données privées
  • Pas de latence réseau
  • Pas de coût API
  • GPU/CPU local

☁️ Modèles distants

  • Performance optimale
  • Toujours à jour
  • Scalabilité
  • Pay-per-use
Ollama permet d'utiliser des modèles comme Llama, Qwen, ou Mistral en local. Les modèles distants offrent plus de puissance mais moins de contrôle.

"Il faut faire confiance aux modèles distants…"

Le petit hic d'Ollama

  • Taille de contexte limitée vs modèles SaaS
  • 8K-32K tokens (Ollama) vs 128K-2M tokens (GPT-4)
  • Impact sur les conversations longues
  • Trade-off : Contrôle vs Performance
Le principal inconvénient d'Ollama par rapport aux modèles SaaS, c'est la taille du contexte. Là où GPT-4 Turbo gère 128K tokens et Claude jusqu'à 2M tokens, les modèles Ollama sont généralement limités à 8K-32K tokens. Ça peut poser problème pour les conversations très longues ou l'analyse de gros documents. Mais c'est le prix à payer pour garder le contrôle !

Model Selector

  • Basculement automatique

Cette fonctionnalité est très pratique : on peut changer de modèle dynamiquement selon des variables, le type de tâche, ou implémenter des fallbacks si un modèle est indisponible. Parfait pour optimiser coûts et performances selon le contexte.

Mémoire

  • Historique & apprentissage
La mémoire permet aux agents de maintenir le contexte dans les conversations, de persister l'état entre workflows, et d'apprendre des interactions précédentes grâce à l'historique.

Interface Chat : Embedded vs Hosted

🏠 Embedded

  • Widget intégré
  • Votre design
  • Contrôle total

☁️ Hosted

  • Page dédiée
  • Prêt à l'emploi
  • Déploiement rapide
n8n propose deux modes d'interaction avec vos agents : embedded pour intégrer le chat dans vos applications existantes avec votre propre design, ou hosted pour une page de chat dédiée et prête à l'emploi. Parfait pour tester rapidement ou déployer un chatbot interne.

Sécurité

  • Noeud Guardrails (entrée/sortie)
  • Modèles de guardrails disponibles:
    • Llama Guard (modèle local open-source)
    • granite3-guardian (pareil)
  • Exécution locale possible sans API externe
  • Contrôle complet sur vos données sensibles

Human In Loop

  • Pause et approbation manuelle dans le workflow
  • L'IA demande validation avant d'exécuter une action
  • Améliore la confiance et la contrôlabilité
  • Outils disponibles:
    • Wait for webhook
    • Human in the loop node
    • Email de notification
Human In Loop permet de mettre en pause un workflow et d'attendre une approbation manuelle avant de continuer. C'est crucial pour les décisions importantes où vous voulez garder le contrôle humain. N8n propose plusieurs outils pour implémenter cela : webhook, node dédié, ou notifications par email. Cela améliore la confiance dans les systèmes d'IA en garantissant que les actions critiques sont approuvées.

Evaluations

  • Évaluation de la qualité des réponses de l'IA
  • Mesure des performances du workflow
  • Light Evaluations pour tests simples
  • Cas d'usage:
    • Validation de la pertinence des réponses
    • Détection des hallucinations
    • Suivi de la qualité en production
    • A/B testing des prompts
Les évaluations permettent de mesurer et d'améliorer la qualité des réponses de votre agent IA. N8n propose les Light Evaluations pour des tests simples et rapides. Cela permet de valider que votre agent fonctionne correctement avant de le mettre en production. Consultez: https://docs.n8n.io/advanced-ai/evaluations/light-evaluations/

Docker Model Runner simplifie la syntaxe pour déployer des modèles IA avec Docker Compose. Plus lisible et automatisé, mais encore limité à Docker Compose.
